Each check is two sentences and a trigger line: the diff shapes that send you to it, the defect ids behind it in `docs/superpowers/specs/lens-audit/defects.jsonl`, and last the trigger names that point at it, where `floor` means only the tier floor brings this lens there.

Read the cited code for every finding, and state the failure path from the code, never from a check's wording.

## The shape

Lifecycle exists for one shape: the OS is a set of state machines, proposal, invoice, pay period, shift, drink plan, scheduled message, consult chain, opt-out, whose status columns are written in many places and owned by none. A terminal transition does not fan out to its dependents, a late writer acts without re-reading the row, a money write a state predicate refuses vanishes, a predicate such as frozen is inlined four ways, a state or flag has no exit, and a scheduler's first tick reaches further than its author pictured.

## Checks

**LIF-1 The server is the transition authority.** A route that performs or permits a transition enforces the gate itself: it refuses writes after the terminal stamp, never takes a status from `req.body` without validating the from-to pair, enforces the floor or window the client only warns about, treats a render-only flag or a hidden control as no authority, refuses a void on an invoice with payments applied, and requires an explicit confirm token, a 409 without it, on a one-way door. It writes a transition stamp only after its gate resolved, such as sign after `confirmPayment` succeeds, and a kill switch gates every leg of the flow it names, the press-1 bridge included.
Trigger: PUT, PATCH and POST handlers that write a status or lifecycle flag, `req.body.status`, a client control disabled or hidden on a rule the server does not check, an enabled flag read in one leg only, the submit ordering in `PaymentForm.js`, the manual path in `beoFinalize.js`, `shifts.handlers.js`. Defects: D1893, D1907, D1908, D1937, D1938, D1959, D1960, D1966, D1970, D2003, D2004, D2023, D2037, D2046, D2049, D2103. Names: lifecycle.set-status, lifecycle.statuses

**LIF-2 Every state and flag has an exit.** For each status a row can land in and each degraded flag a handler can set, a bad email or phone status, an admin gratuity origin, a terminal suppression reason, a local enrolled flag, the diff names the transition out and who triggers it, a user action, a sweep or a webhook, and an intermediate row inserted before an external call has a reaper. Trigger: a new status value or suppression reason, a webhook or form setting a flag to bad or false, a pending insert before an external call, a reset route with no client caller, a scheduler inventory with no reaper for the new state, `beoFinalize.js`, `shoppingListApprove.js`. Defects: D1953, D1963, D1978, D1980, D1986, D2015, D2025, D2056, D2057, D2060, D2070, D2074, D2102, D2114. Names: floor

**LIF-4 Late and repeated writes read the row first.** A handler that writes to a row it did not just create, a Stripe or Cal.com webhook, a link or session completion, an upsert, a revert, a re-approve, a client re-submit, reads the row's status and admin-set flags inside its transaction and branches: a terminal row gets the ledger write plus an alert and none of the conversion side effects, a lost first-writer-wins commit runs no side effects, an admin-set value is never overwritten by a lower-authority writer, and an approved artifact is served from its approved snapshot. Entry side effects fire on the from-to transition, not on the destination state, and every provider state the handler can receive, processing or a failed intent retried, maps to an OS state the reminder ladder and the Pay CTA respect.

**LIF-5 A refused money write must land somewhere.** Any write that moves money and that a state predicate can refuse, the `amount_paid` credit, a payout line, a tip share, a clawback, a refund row, record-payment, either succeeds, defers with a replayable stamp that a named job replays and a test exercises, or raises a 409 or an alert naming the row, and the diff shows which. An orphan sweep keeps or deletes by the line's full state and never pays someone off the roster, and a sibling action keyed on a shared client or booker identity tells admin-adjusted rows from auto-drafts and alerts before discarding admin work, minting a bookable sibling at catalog price or cancelling a real consult.

**LIF-7 Terminal-state fan-out.** When a row moves into a terminal or losing state, archived or cancelled, a full refund, an invoice void, an option-group loser, a regenerated link, a staffer removed, enumerate every dependent live object and close it in the same path or state which survive: shifts and their requests, scheduled messages in every non-terminal status, PaymentIntents on every surviving invoice including partially paid ones, prior links, the out-of-area lock, ungrouped siblings, the events feed and the auto-assign candidates. **LIF-14 Opt-out writes are scoped, and automated sends write their row.** A write that records a refusal names what was refused and by whom: an un-ticked consent box writes nothing, a later ticked submit from the same address records consent instead of resolving as existing, and a STOP or a carrier 21610 is recorded against the line that received it and the person who sent it, never an internal alert number or every row sharing those digits. **LIF-15 First-run and flip-on blast radius is computed and shipped dark.** For every new scheduler, sweep, flag or widened predicate, state what the first tick does against the production table today and how many rows match, ship it behind an opt-in flag or a dry run as the stale-proposal sweep's flag pair does, and age-bound the predicate so a flip or a redeploy does not retro-process the backlog. A sweeper whose provider filter can be null goes account-wide, so its candidate rows are bounded before the first call.
Trigger: a new block in the scheduler section of `server/index.js`, a new run or enabled variable, a sweep SELECT with no creation or schedule bound, a path that enqueues historical rows when a flag turns on. **LIF-16 Who runs the job, and one bad row never ends the tick.** A scheduler registers only through `enabled` behind the global schedule switch in `server/index.js`, so a non-production process never fires and a secondary instance can be switched off, and its per-row work is also claimed with a conditional UPDATE so N instances cannot double-charge or double-send when the flag is wrong. Per-row work is wrapped so one bad row is logged and skipped without ending the tick for every other row.
Trigger: a timer started in the listen callback outside `enabled`, a job that sends or charges with no claim, a per-row loop with no per-row catch, an instance-count change in render config. Defects: D1739, D1761, D1765, D2397, D2399. Names: lifecycle.set-interval, lifecycle.scheduler-paths

**LIF-17 A backstop arm defers, never preempts.** A sweep that re-fires work an in-process timer owns fires only when the primary provably died, a stale claim or a missing heartbeat, defers by at least the primary's own delay, and recomputes copy and timing from the current row, so an eve text re-dispatched days out never says tomorrow. A reschedule DELETE excludes processing rows so it never erases a live claim.
Trigger: a sweep arm whose predicate is row unfinished rather than primary dead, a stored message body replayed by a reaper, a reschedule or purge DELETE that includes processing. Defects: D1635, D1746, D1747, D2408. Names: lifecycle.scheduler-paths, lifecycle.set-interval

**LIF-18 Caps count an append-only ledger.** A daily or rolling cap sums rows that no transition, reschedule, cancel or prune deletes, such as `call_audit` or the menu-art reservations, never a state table, and a cap that excludes skipped rows has a second counter on the billed act itself. A throttle window starts at the first event in the window and is not reopened by each stop, and the cap's comment names the ledger it counts.
Trigger: a COUNT or SUM feeding a cap or throttle, a counted table that another file deletes from, a skipped-status exclusion in a cap predicate, a window variable assigned inside the handler it bounds. Defects: D2403, D2404, D2405. Names: lifecycle.scheduler-paths

**LIF-19 Alerts from a loop are throttled per entity.** A sweep that finds the same bad row every tick alerts once per window by claiming an alerted stamp in the UPDATE with `WHERE alerted_at IS NULL RETURNING`, or a dated throttle row. An in-memory last-alert time is acceptable for Sentry noise only, never for a client or staff send, because it resets on restart and a check-then-send-then-log order lets concurrent retries both pass.
Trigger: `notifyAdmin`, `sendEmail`, `sendSMS` or `sendPush` inside a sweep loop or a webhook retry path, a 60-second sweep that can re-find a row, a throttle read then send then write. Defects: D1721, D2405, D2416. Names: lifecycle.scheduler-paths, lifecycle.set-interval

**LIF-20 A missing or malformed filter aborts, never widens.** A script with `--apply` defaults to a dry run, parses its filter strictly so a NaN or empty `--only` aborts, prints the candidate count, and refuses to apply above the stated expectation without an explicit override, and in SQL an ANY over an empty array short-circuits before any write. A provider list call never runs with a null filter, because stripe-node drops undefined parameters and a refund list by a null intent lists the whole account, so the SELECT guards with IS NOT NULL and the call refuses a missing key.
Trigger: an `--apply` flag, an argv parse feeding a WHERE, a Stripe list call whose filter can be null, ANY over an array built from input. Defects: D2394, D2396, D2412. Names: lifecycle.scheduler-paths

**LIF-21 Prune and retention jobs name the copies and counters they feed.** A DELETE in a prune or retention job states whether the provider-side object, such as a call recording, is deleted or deliberately kept, and keeps its retention longer than any cap window that counts the table. It never deletes rows a healer, a hold or the payroll orphan sweep still reads, such as positive payroll adjustments.
Trigger: a DELETE in a scheduler, sweep or prune file or in `payrollAccrual.js`, a retention interval change, a new cap counting a pruned table. Defects: D2394, D2403, D2420. Names: lifecycle.scheduler-paths

## Output

- H1 `server/routes/example.js:120` The defect in one sentence. Failure path: the input and the steps that make it bite. Check: LIF-1.
