# Instruction rewrite, step 3: the gate on the range, the ship path, the watch, dormant

**Goal:** build the push half of "main is prod" as scripts with tests, all dormant behind a flip marker that step 5 writes: a gate that tests a commit in isolation, classified by the push range; one push path that checks the review receipts over the range, gates, pushes the literal sha and starts a watch; a watch that waits for the deploy and reads Sentry against a baseline; two markers every push path refuses on; and the session-start line that prints them. Until the marker exists nothing about pushing changes: `npm run gate` and a literal-sha push stay the way, the hook falls through to today's fingerprint check, and the board writer keeps its guarded push.

**Spec:** `docs/superpowers/specs/2026-10-19-instruction-rewrite-design.md` (rev 6), sections 3.7, 3.10, 3.11, 4.1 to 4.8, 7, 8 (step 3), 9, D1 to D4, D11. The step 2 plan's "Contracts shared across lanes" (the receipt, the keys, the tier, the locks, the smoke summary) binds this step as built, through its "Amendments (rev 3, as built)".

**Decisions this plan makes on what the spec left to the builder (section 9), stated here so Dallas sees them:**

1. **The flip marker is `<git-common-dir>/drb-flip.json`**, `{sha, pushed_at, written_by}`, written by step 5's shipping session after the flip push is confirmed on origin and read by every push path from this step on. The spec names the marker without a path; the common dir is where every worktree of the repo sees one file, and this box is the only pusher.
2. **The sha gate receipt is keyed on the sha alone and records the tree hash without keying on it.** A review-time smoke runs in the lane's checkout under the box's `.env`; the gate's worth is its environment (its own env file, a private `npm ci` when a lock changed), so honoring a smoke run elsewhere would hand back exactly what the gate adds. The tree hash is recorded so a later step can change this without a receipt format change. Cost: one eight-minute smoke per tier A ship on top of the review's.
3. **The gate env file** holds `NODE_ENV=test`, `SEND_NOTIFICATIONS=false`, `RUN_SCHEDULERS=false`, a fixed throwaway `JWT_SECRET`, a fixed throwaway 64-hex `ENCRYPTION_KEY`, and `STRIPE_TEST_MODE_UNTIL=` (empty), and no Stripe key: the box's `.env` carries live keys only and no `*_TEST` credential (names checked 2026-10-22), and the money smoke suites that touch Stripe fake it through the `getStripe` seam (`stripeCreateIntent.test.js` is the precedent). `getStripe()` therefore returns null inside the gate, and a suite that fails for want of a key is a suite reaching live Stripe from the gate, a finding against the suite and never a reason to copy a live key in. `DATABASE_URL` is set per suite by `testdb-smoke.js` (ci-smoke). The smoke is spawned with a scrubbed environment (PATH, HOME, LANG, TMPDIR, `NEON_API_KEY` when set, and the file's variables; nothing else inherited), because dotenv never overrides a variable already in the process. The gate-sha lane verifies the set by running the full smoke with it once; a variable it adds is named in the lane report with the suite that needed it.
4. **No `client/.env` in the gate worktree.** The build gate compiles; a missing `REACT_APP_*` bakes an empty string, which the gate does not judge, and the Vercel build carries its own environment.
5. **The watch window is ten minutes after the deploy is observed, polling every twenty seconds; the deploy wait bound is twenty minutes for Render and fifteen for Vercel**, counted from the push. The Sentry read is the project events endpoint (`/api/0/projects/dr-bartender/<project>/events/`) with the token from `~/.sentryclirc`, paged newest-first until the window's start, for two windows of equal length either side of the deploy instant, grouped by issue: an issue with no events in the pre-window counts in full, an issue with events in both counts only when the post-window count exceeds the pre-window count. `sentry-cli events list` has no time filter and the issues endpoint would miss events on a resolved issue, which 3.11 says must count. The health URL is the Render service's own (`https://os-g7oa.onrender.com/api/health`, from `render services`), the Vercel check is `vercel ls os --scope drbartenders-projects --format json` filtered to `target: production` and `meta.githubCommitSha` equal to the sha, state `READY`.
6. **The ship log is one line per event**, `<ISO time> <stage> <text>`, at `<git-common-dir>/drb-ship/<sha>.log`, ending in exactly one `result <ok|refused|failed|pushed-elsewhere> <text>` line; beside it `<sha>.json` is the manifest (`sha`, `base`, `started_at`, `docs_only`, `touches_server`, `touches_client`, `gate`, `pushed_at`, `result`, `watch`) the watch and lane-status read, `<sha>.watch.log` the watch's own log, and `drb-ship/last` holds the sha of the latest ship started. `lane:status` reads the manifest, never the log's prose.
7. **The SessionStart hook runs `node scripts/show-location.js && node scripts/lane-status.js --session-start`.** `--session-start` prints the markers, the flip state, the last ship, an in-flight ship and the stale lanes in at most a dozen lines and exits 0 whatever it finds, a caught crash included (one line naming it). The plain CLI keeps its non-zero exit on a stale lane.
8. **The receipt check over a range reads every commit in `origin/main..sha`**, and for each: docs-only by 4.7 needs no receipt; otherwise a receipt must exist under `commitKey(parent, commit)` (kinds lane, commit, squash, revert, comment-only) or under the commit's tree hash (kind quick-fix), be final, carry a tier no lower than `tierFromGit` computes for `parent..commit` now, list every file of that diff (generated docs excluded) in `coverage.files_in_diff` with none left in `not_reached` unless `allowed_not_reached`, and for tier A carry a smoke entry with `fail 0` and `skipped false`. A merge commit in the range is refused (main holds squashes only). The hook and `ship` call the one function.
9. **A clean revert is recognized by `ship`** when the commit message carries `This reverts commit <sha>` and `commitKey(parent, commit)` equals the pinned patch id of `git diff <reverted> <reverted>^` (the reverse diff); `ship` then writes a `revert` receipt (`written_by: ship`, no lenses, the reverted sha recorded) before the range check, so D2 passes by construction, and runs the gate only (4.8).
10. **Lock order: ship, then push-gate, then smoke.** `ship` takes `<git-common-dir>/drb-ship.lock` blocking through `flockExec.underLock`; sha mode keeps today's non-blocking `drb-push-gate.lock` (a second gate refuses, as today, so two gates never reset ci-smoke under each other even when one runs by hand outside `ship`); the smoke takes its own lock inside. The hook's new path takes no lock (4.3). `merge-lane.sh` keeps `merge-lane.lock` until step 5 moves it onto the ship lock.
11. **The gate worktree lives at `<worktrees dir>/.gate-<sha7>/`**, detached, beside the lanes on the same filesystem (a private `npm ci` is too large for a tmpfs), removed in an exit trap and on every signal, and swept on the next gate start when a crash left one (`git worktree prune` plus the directory). `lane-status` never lists it: it is detached and `listLanes` keeps branches only.
12. **`ship` detaches by default** (spec 4.1: the foreground limit is ten minutes and a tier A gate is longer), prints `ship: started <sha7>, log <path>` and exits 0 at once; the session reads the log for the `result` line. `--foreground` keeps it attached (tests, and the board writer, which needs the result in its loop). `--status [<sha>]` prints the manifest and the log's last lines.
13. **`--ack-watch <sha> --note <text>`** clears the watch marker only when it names that sha, writes the note to that ship's log as an `ack` line, and pushes nothing; the note is the "what it saw and decided" of 4.4 and the ship report quotes it.
14. **The hook's new path validates every pushed ref against `origin/main`**, not only `main`: a lane branch pushed to origin for backup would need receipts for its commits, which it has by the time it is reviewed, and `--no-verify` stays the named escape.
15. **`worktree:new` takes over the lane memory-root link** from the `drb` wrapper (6.5; the wrapper's own comment says step 3 does this), linking `~/.claude/projects/<key>/memory` to the main memory with the wrapper's archive rule for a real directory; the wrapper keeps its link code as a fallback for a worktree made before this step.

## Review focus

The five ways this step bites, each pinned to a check:

1. The legacy gate or the hook regresses before the flip, so the flip push itself (which goes through the legacy path) fails or, worse, passes ungated: the 29 existing push-gate cases stay byte-for-byte and green, `verify` with no flip marker behaves as today on every stdin shape, and `npm run gate` on the real tree still writes today's receipt (gate-sha, checks 1 and 2).
2. The sha gate classifies from the tip commit instead of the range, or honors a receipt from before origin/main moved, so a money change earlier in the range ships without the smoke: the classification cases cover a server change two commits back and a receipt whose recorded base is no longer origin/main (gate-sha, checks 3 and 6).
3. A commit with no receipt, a receipt whose coverage is short, or a tier A receipt with no smoke, passes the range check: each is a refusal case with a real receipt written through `receipt.js` (ship-lib, check 3).
4. The ship lock, the gate lock and the smoke lock take each other in the wrong order or a detached ship leaves no result line, so two ships interleave or the window waits on a log that never ends: the lock-order test and the kill-mid-ship test (ship, checks 4 and 5).
5. The session-start hook exits non-zero or hangs, breaking every session, or the board writer pushes other windows' commits before the marker: `--session-start` on a repo with a broken marker file exits 0 in under two seconds, and the board writer without the marker is the untouched guard (status-and-board, checks 1 and 4).

## Contracts shared across lanes

These are the decisions the lanes build to; a lane that finds one wrong rules and ledgers it like the step 2 plan did.

**The common dir layout.** Everything this step writes outside the tree lives under `git rev-parse --path-format=absolute --git-common-dir`, resolved from the cwd through `receipt.commonDir`: `drb-flip.json` (read only this step), `drb-markers/gate.json`, `drb-markers/watch.json`, `drb-gate/<sha>.json`, `drb-ship/<sha>.log`, `drb-ship/<sha>.json`, `drb-ship/<sha>.watch.log`, `drb-ship/last`, `drb-ship.lock`. The existing `drb-push-gate-receipt.json` (per worktree, `--absolute-git-dir`), `drb-push-gate.lock`, `drb-smoke.lock`, `drb-devdb.lock`, `merge-lane.lock` and `drb-review/` are unchanged. Every write is atomic (temp file plus rename, the pattern `receipt.js` uses).

**`scripts/lib/markers.js`.** `flip({cwd})` returns `{sha, pushed_at, written_by}` or null; `gate({cwd})` and `watch({cwd})` return the marker or null; `setGate({sha, reason, gates})`, `clearGateIfDescendant(sha)` (clears when the marker's sha is an ancestor of the given sha, returns what it did), `setWatch({sha, deploy_at, count, by_issue})`, `clearWatch(sha)` (only when the marker names that sha; returns false otherwise); `standing({cwd})` returns `{gate, watch}` for the refusal line every push path prints: `BLOCKED: gate marker stands on <sha7> (<reason>); fix forward and ship again` and `BLOCKED: watch marker stands on <sha7> (<count> events since deploy); read them, then npm run ship -- --ack-watch <sha7> --note <what you saw and decided>`. A marker file that is not JSON is reported as standing with the reason `unreadable marker <path>`; never silently absent.

**`scripts/lib/shipLog.js`.** `open(sha, {cwd})` creates the log and the manifest and writes `last`; `line(sha, stage, text)` appends one `<ISO> <stage> <text>` line (stages: `start`, `fetch`, `range`, `receipts`, `revert`, `gate`, `push`, `watch`, `ack`, `result`); `setManifest(sha, patch)` merges fields atomically; `readManifest(sha)`, `readLast()`, `tail(sha, n)`; `inFlight({cwd})` returns the newest manifest with no `result`, if its log was written to in the last two hours, else null. Text written to a log passes through `piiShapes.mask` in the pre-step's allowlisted mode, so a path or a commit subject with a shape never lands in a file lane-status prints.

**`scripts/lib/rangeCheck.js`.** `checkRange({base, tip, cwd})` returns `{ok, docs_only, commits: [{sha, subject, docs_only, receipt: {key, kind, tier} | null, problems: []}], pii: [{file, line, shape}], problems: []}`. Per commit the rules of decision 8. The PII scan is `piiShapes.findInDiff` over the pinned diff of `base..tip` in the pre-step's allowlisted mode; any hit is a problem. `docsOnly(base, tip)` is `sensitive-match.isDocsOnly` over `git diff --name-only base tip`; `touches(base, tip)` returns `{server, client, money_paths, install}` from `push-gate.MONEY_PATHS`, `CLIENT_PATHS` and the four lock and manifest paths. A commit review's `written_by` is not checked (the receipt is a local file, not a privilege boundary, 3.7); the receipt's content is.

**The sha gate receipt.** `drb-gate/<sha>.json`: `{version: 1, sha, tree, base, files, gates_needed, gates_passed, nothing_to_run, static_checks: {blocking, file}, node_modules: 'linked' | 'npm ci', env_keys: [names], started_at, finished_at}`. Valid for a push when the sha matches, `base` equals the current `origin/main` after the fetch, every needed gate is in `gates_passed` (or `nothing_to_run`), and `finished_at` is under seven days old. A money gate that skipped for want of a key is never in `gates_passed` (guard 5 kept).

**`push-gate.js` modes.** `run [ref]` (legacy, unchanged), `verify` (the hook's; reads the flip marker: absent, today's path including its lock; present, the new path with no lock: deletes and empty stdin as today, malformed refuses as today, then per pushed sha the markers, the sha receipt, `rangeCheck`), `sha <sha> [--base <ref>]` (the gate in a worktree; writes the receipt; sets the gate marker on failure and clears it on a descendant pass; prints the receipt path; exits 1 on any failure), `receipt <sha>` (prints the receipt or `none`). Exports for tests and for `ship`: `classifyRange(base, tip)`, `checkShaReceipt(receipt, {sha, base, needed, now})`, `gateEnvFile()` (the text of decision 3), `gateWorktreePath(sha)`, and the existing exports. `MONEY_PATHS` gains `scripts/lib/worktreeLinks.js` and `scripts/lib/rangeCheck.js` (both change what the gate runs or allows). A classification that touches `server/` or `client/` also runs `static-checks.js --base <base> --tip <sha>` in the worktree; a blocking finding fails the gate with the file named.

**`scripts/lib/worktreeLinks.js`.** `LINKS`: `[{rel: 'node_modules', shared: true}, {rel: 'client/node_modules', shared: true}, {rel: '.husky/_', shared: true}, {rel: '.env', shared: false}, {rel: 'client/.env', shared: false}]`; `linkInto(target, mainRoot, {env: boolean, log})` makes the shared links always and the env links only with `env: true`, with worktree-new's existing rules (skip a missing source with a warning, leave a real path in place, report an existing link); `unlinkFrom(target)` removes link entries only (worktree-rm's order). `memoryRoot(worktreePath)` returns the Claude Code project memory path for a folder (`$HOME/.claude/projects/<path with slashes as dashes>/memory`); `linkMemory(worktreePath, mainMemory)` applies the wrapper's rule (a link is left; a real directory is archived under `<mainMemory>/_archive/lane-<name>-<file>` then replaced; anything else refuses). `worktree-new.js` calls `linkInto(target, mainRoot, {env: true})` and `linkMemory`; the gate calls `linkInto(wt, mainRoot, {env: false})` and writes its own `.env`.
